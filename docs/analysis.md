# Анализ предметной области: AccessEvent

## 1. Описание предметной области

AccessEvent — веб-платформа для организации и проведения мероприятий с особым акцентом на доступность для людей с нарушениями слуха. Система объединяет организаторов и участников, предоставляя инструменты для создания мероприятий, регистрации, визуальных уведомлений (вместо звуковых), текстового чата и обратной связи. Ключевая особенность — все коммуникации дублируются в текстовом/визуальном формате, что делает платформу инклюзивной.

## 2. Сущности и атрибуты

| Сущность | Атрибуты | Описание |
|----------|----------|----------|
| **User** | id, name, email, password_hash, phone, role, hearing_status, created_at | Базовый пользователь платформы (организатор, участник, админ) |
| **Event** | id, organizer_id, category_id, title, description, date_start, date_end, location, is_inclusive, capacity, status | Мероприятие |
| **Category** | id, name, description | Категория мероприятия (концерт, лекция, мастер-класс и т.д.) |
| **Registration** | id, event_id, participant_id, status, created_at, updated_at | Регистрация участника на мероприятие |
| **Notification** | id, event_id, user_id, type, message, color, scheduled_at, sent_at | Визуальное уведомление (баннер/пуш) |
| **ChatMessage** | id, event_id, sender_id, text, created_at, is_read | Сообщение в текстовом чате мероприятия |
| **Review** | id, event_id, participant_id, rating, text, created_at | Отзыв участника о мероприятии |
| **AccessibilityOption** | id, event_id, type, description | Опция доступности (сурдоперевод, субтитры, текстовая трансляция) |

## 3. Бизнес-процессы

### 3.1. Создание мероприятия
Организатор заполняет форму: название, описание, дата/время, место, категория, вместимость. Отмечает флаг `is_inclusive` и выбирает опции доступности (сурдоперевод, субтитры и т.п.). Мероприятие сохраняется со статусом «черновик» → «опубликовано».

### 3.2. Регистрация на мероприятие
Участник находит мероприятие через поиск/категории, нажимает «Зарегистрироваться». Создаётся запись `Registration` со статусом `pending`. Организатор одобряет или отклоняет: `pending → approved / rejected`. При одобрении участнику отправляется визуальное подтверждение.

### 3.3. Визуальное уведомление
Планировщик проверяет время начала мероприятия и рассылает цветные баннеры:
- 🟡 **Жёлтый** — за 30 минут до начала («Скоро начало»)
- 🟢 **Зелёный** — в момент старта («Мероприятие началось»)
- 🔴 **Красный** — при отмене или переносе («Отменено»)

Уведомление сохраняется в `Notification` и отображается в личном кабинете и на странице события.

### 3.4. Текстовый чат
На странице мероприятия доступен общий чат. Участники и организатор обмениваются текстовыми сообщениями (`ChatMessage`). Новые сообщения подсвечиваются визуально, возможна индикация непрочитанных. Чат работает в реальном времени (WebSocket) или с периодическим обновлением.

### 3.5. Отзыв на мероприятие
После завершения (`date_end` прошла) участник со статусом `approved` может оставить отзыв: оценка 1–5 и текст. Отзыв сохраняется в `Review`, влияет на рейтинг организатора.

### 3.6. Управление доступностью
Организатор при создании мероприятия добавляет `AccessibilityOption`: сурдоперевод, субтитры, текстовая расшифровка, ассистивные технологии. Участники видят эти опции в карточке мероприятия и могут фильтровать события по ним.

## 4. Роли пользователей

- **Организатор** — создаёт мероприятия, управляет регистрациями, отвечает в чате, настраивает опции доступности
- **Участник** — ищет мероприятия, регистрируется, получает визуальные уведомления, общается в чате, оставляет отзывы
- **Администратор** — модерирует платформу, управляет категориями, блокирует нарушителей
- **Гость** — просматривает каталог мероприятий и описания без регистрации
